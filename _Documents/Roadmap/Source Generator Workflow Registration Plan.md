# Roadmap: Source Generator for Automated Workflow Registration

## 1. Executive Summary

As the number of workflows, signals, and commands grows in an enterprise project, manual registration becomes a developer bottleneck and a source of runtime errors. Reflection-based auto-registration (e.g., `RegisterFromAssemblyContaining<T>`) solves developer overhead but introduces startup latency and breaks Native AOT (Ahead-Of-Time) compilation compatibility.

This plan details the design of a Roslyn **Source Generator** that automatically discovers workflow classes, validates their structure at compile time, and emits optimized, static, AOT-safe registration code to populate the [WorkflowDefinitionRegistry](file:///d:/MySrc/Workflows/Workflows.Definition/Registration/WorkflowDefinitionRegistry.cs).

---

## 2. Current Registration Mechanics & Limitations

### The Reflection Model
Currently, workflows are registered in two ways:
1. **Manual Registration**:
   ```csharp
   builder.RegisterWorkflow<OrderProcessingWorkflow>("OrderWorkflow", 1);
   ```
2. **Reflection-Based Assembly Scanning**:
   ```csharp
   builder.RegisterFromAssemblyContaining<OrderProcessingWorkflow>();
   ```

### Limitations:
* **Startup Performance Overhead**: Scanning large assemblies for types during startup incurs significant performance costs on serverless environments or cold starts.
* **AOT Incompatibility**: Reflection APIs like `Assembly.GetTypes()` and `MakeGenericMethod()` block compiler optimization and prevent Native AOT trimming.
* **Late Feedback Loop**: Structural violations (e.g., a workflow class that is not marked `sealed` or is missing the `[Workflow]` attribute) are only caught at runtime.

---

## 3. Proposed Source Generator Design

The source generator will monitor the compilation for types inheriting from `WorkflowContainer` and automatically implement the `DI.RegisterWorkflows` extension method at compile time.

```mermaid
graph TD
    A[C# Compiler starts] --> B[Source Generator Scans AST]
    B --> C{Inherits WorkflowContainer?}
    C -- Yes --> D{Is Sealed & has [Workflow] Attribute?}
    D -- No --> E[Emit Compile-time Error/Diagnostic]
    D -- Yes --> F[Extract Metadata & Signal/Command references]
    F --> G[Generate static registration code]
    G --> H[Emit DI.g.cs containing RegisterGeneratedWorkflows]
```

### Compile-Time Code Analysis
The source generator will inspect:
1. **Class Declarations**: Classes inheriting from [WorkflowContainer](file:///d:/MySrc/Workflows/Workflows.Definition/WorkflowContainer-Base.cs).
2. **Attributes**: Read the name and version from `[Workflow("Name", Version)]`.
3. **Method Bodies**: Scan the `Run` method for calls to `WaitSignal<TSignal>("Identifier")` and `WaitCommand<TCommand, TResult>("Identifier")` to automatically discover and register signals/commands without explicit declaration.

## 4. Generated Code Blueprint

Given the following user workflow code:

```csharp
namespace MyCompany.Workflows
{
    [Workflow("OrderWorkflow", 2)]
    public sealed class OrderWorkflow : WorkflowContainer
    {
        public async IAsyncEnumerable<Wait> Run()
        {
            yield return WaitSignal<OrderPaidSignal>("OrderPaid");
        }
    }
}
```

The Source Generator will emit a partial class implementation `DI.g.cs`:

```csharp
// <auto-generated/>
using System;
using Microsoft.Extensions.DependencyInjection;
using Workflows.Definition.Registration;

namespace Workflows.Definition
{
    public static partial class DI
    {
        /// <summary>
        /// Automatically generated method containing optimized static registrations for all discovered workflows.
        /// </summary>
        public static IServiceCollection RegisterWorkflows(this IServiceCollection services, Action<IWorkflowBuilder> register)
        {
            // Fallback for custom manual registration callbacks
            register?.Invoke(new GeneratedWorkflowBuilder());
            return services;
        }

        private class GeneratedWorkflowBuilder : IWorkflowBuilder
        {
            public IWorkflowBuilder RegisterWorkflow<T>() where T : WorkflowContainer
            {
                // Core registration logic...
                return this;
            }

            // Implement other IWorkflowBuilder members...
        }
        
        public static IWorkflowBuilder RegisterGeneratedWorkflows(this IWorkflowBuilder builder)
        {
            // Direct call to avoid reflection:
            builder.RegisterWorkflow<MyCompany.Workflows.OrderWorkflow>("OrderWorkflow", 2);
            
            // Automatically discovered signals:
            builder.RegisterSignal<MyCompany.Workflows.OrderPaidSignal>("OrderPaid");
            
            return builder;
        }
    }
}
```

## 5. Compile-Time Diagnostics (Analyzer Rules)

To prevent runtime failures early, the analyzer component of the generator will emit compiler errors (diagnostics) for structural issues:

| Diagnostic ID | Severity | Description | Rule / Trigger |
| :--- | :--- | :--- | :--- |
| **WF0001** | **Error** | Non-sealed workflow class. | Class inherits from `WorkflowContainer` but is not marked `sealed`. |
| **WF0002** | **Error** | Missing `[Workflow]` attribute. | Class inherits from `WorkflowContainer` but lacks the `[Workflow]` attribute. |
| **WF0003** | **Warning** | Missing `Run` method. | Workflow has no async generator method named `Run` returning `IAsyncEnumerable<Wait>`. |
| **WF0004** | **Error** | Duplicate workflow identity. | Two workflow classes share the same name and version number. |

## 6. Implementation Stages

### Stage 1: Setup Infrastructure
* Add a new project `Workflows.Analyzers` (targeting `.NET Standard 2.0` as required for Roslyn analyzers).
* Configure the generator reference inside `Workflows.Definition.csproj`.

### Stage 2: Syntax and Semantic Receivers
* Implement `ISyntaxContextReceiver` to capture class declarations inheriting from `WorkflowContainer`.
* Use semantic model analysis to extract namespace, class names, attribute parameters, and generic invocations inside the `Run` methods.

### Stage 3: Code Generation & Registration
* Generate partial implementation of [DI.cs](file:///d:/MySrc/Workflows/Workflows.Definition/DI.cs) implementing `RegisterWorkflows` to automatically call the static generated registration lists.

### Stage 4: Testing & Verification
* Write integration tests under `Tests/Workflows.Runner.Tests` to verify that AOT-safe generated methods produce identical `WorkflowDefinitionRegistry` tables compared to manual/reflection-based registries.
