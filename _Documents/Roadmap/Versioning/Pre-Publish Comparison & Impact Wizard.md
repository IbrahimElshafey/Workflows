# 🧙‍♂️ WF Tools: Pre-Publish Comparison & Impact Wizard

## 1. Overview

The **Pre-Publish Comparison & Impact Wizard** is a core component of the **WF Tools suite** (`dotnet-wf` CLI and embedded Admin UI Wizard). It analyzes workflow assemblies, verifies schema compatibility, generates schema contracts, creates migration boilerplate classes, and produces a deterministic **`deployment-manifest.json`** for deployment pipelines.

### 1. Offline Assembly Comparison (Default Mode)
- Runs completely **offline by default** without requiring a live database connection access.
- Ideal for CI/CD pipelines, local developer environments, and git pre-commit hooks.
- Compares `WorkflowV1.dll` vs `WorkflowV2.dll` using Roslyn AST parsing to detect yield checkpoint shifts, property renames, and structural state machine drift.
- *(Optional)* If a `--db` connection string is provided, the tool enhances the report with live active instance metrics from the target environment.

### 2. Versioned JSON Schema Contract Generation
When WF Tools analyzes an assembly version, it automatically generates a standardized **`WorkflowName_vX_Schema.json`** file for each workflow definition.

```json
{
  "WorkflowName": "OrderProcessingWorkflow",
  "Version": 2,
  "AssemblyVersion": "2.0.0.0",
  "StateClass": "OrderProcessingState",
  "Checkpoints": [
    { "Index": 0, "Type": "SignalWait", "Name": "OrderSubmittedSignal", "StateType": "OrderSubmittedEvent" },
    { "Index": 1, "Type": "TimeWait", "Name": "GracePeriodTimer", "DurationSeconds": 300 },
    { "Index": 2, "Type": "GroupWait", "Name": "FulfillmentGroup", "GroupType": "MatchAll" }
  ],
  "Properties": {
    "CurrentOrderId": "System.Int32",
    "CurrentCustomer": "System.String"
  }
}
```
These schema JSON files are saved in-project under `_Schemas/` and act as immutable baseline contracts for future version comparisons.

### 3. Automated Migration Boilerplate Generation
When breaking structural changes are detected between V1 and V2, WF Tools provides an option (`dotnet wf migrate --old V1.dll --new V2.dll --out ./Migrations`) to **automatically generate strongly-typed C# migration classes**:


### 4. Manifest Persistence (`deployment-manifest.json`)
Decisions made during wizard execution or CLI runs are saved to a **`deployment-manifest.json`** file saved both **in-project** (for version control auditing) and **with the published build artifacts**.

```json
{
  "DeploymentId": "dep_20260728_001",
  "SourceAssembly": "MyCompany.Workflows.dll",
  "TargetVersion": 2,
  "CreatedUtc": "2026-07-28T02:50:00Z",
  "Workflows": [
    {
      "WorkflowName": "InvoiceWorkflow",
      "Status": "Unchanged",
      "Strategy": "InstantFullReplacement"
    },
    {
      "WorkflowName": "OrderProcessingWorkflow",
      "Status": "Changed_BreakingDrift",
      "Strategy": "ExecuteMigrationScriptThenDropV1",
      "MigrationClass": "OrderProcessingWorkflowMigration_V1_To_V2"
    }
  ],
  "SupervisorInstruction": {
    "DropOldWorkerImmediately": true,
    "TargetWorkerVersion": "2.0.0"
  }
}
```
The **Host Supervisor** reads this manifest during deployment to execute the exact plan deterministically without manual intervention.

## 3. Recommended Deployment Decision Matrix

| Scenario | Offline Analysis Result | Live DB Active V1 Instances (Optional) | Migration Script Present? | Manifest Strategy | Host Supervisor Action |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. Unchanged** | Identical AST | N/A | N/A | `InstantFullReplacement` | Activate V2 Worker, drop V1 instantly. |
| **2. Changed Workflow** | Breaking Drift | **0 instances** | N/A | `InstantFullReplacement` | Drop V1 Worker instantly, activate V2 Worker. |
| **3. Changed Workflow** | Breaking Drift | **> 0 instances** | ✅ Yes (`WorkflowMigration`) | `ExecuteMigrationThenDropV1` | Run DB migration script, upgrade DB rows to V2, drop V1 Worker instantly. |
| **4. Changed Workflow** | Breaking Drift | **> 0 instances** | ❌ No | `SideBySideWorkerSpinUp` | Spin up V2 Worker alongside V1 Worker. Drain V1 instances to 0, then auto-terminate V1. |
